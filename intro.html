04 · ACCESSIBILITY

웹 접근성(Accessibility) 3대 매너

사용자 누구나 편안하게 읽고 조작할 수 있도록 디자인 단계에서 반드시 지켜야 할 기본 규칙입니다.

1. 명도대비 (너무 연하게 쓰지 않기)

배경색과 글자색의 차이가 적어 글씨가 너무 연하면 눈이 피로하고 글자를 읽기 힘듭니다. 바탕과 확실히 대비되는 진한 색상을 사용하여 눈에 잘 띄도록 합니다.

2. 글자크기 (최소 크기 유지)

데스크톱 본문은 최소 16px 이상을 기본으로 설정합니다. 가독성을 해치는 지나치게 작은 글씨는 피하고, 중요한 정보일수록 위계에 맞춰 크기를 키워줍니다.

3. 터치 및 조작 영역 (충분한 버튼 크기)

버튼이나 클릭해야 하는 링크 요소가 너무 작으면 손가락으로 누르거나 마우스로 클릭하기 어렵습니다. 최소 44×44px 이상의 충분한 조작 영역과 여백을 확보해 오작동을 방지합니다.

05 · USEFUL PLUGINS

추천 피그마 플러그인 목록

🎨 Lucide Icons / Feather Icons

웹 표준 개발에서 가장 흔히 쓰이는 깔끔한 벡터 아이콘 라이브러리를 피그마에 즉시 불러옵니다.

🖼️ Unsplash

카드나 히어로 영역에 들어갈 고화질 실사 이미지를 클릭 한 번으로 무작위 적용할 수 있습니다.

Contrast Checker

선택한 글자색과 배경색의 명암비가 웹 접근성 표준(WCAG AA/AAA)을 충족하는지 실시간 검수합니다.

Content Reel

더미 데이터(사람 이름, 프로필 사진, 날짜, 주소 등)를 드래그 한 번으로 채워 넣을 수 있습니다.

반복 UI의 컴포넌트화와 상태 관리

• Main Component (❖): 디자인의 원본을 만들어두고 변경 사항을 한 번에 업데이트합니다.

• Variants: Hover, Active, Disabled 등 버튼이나 입력창의 상태별 디자인을 한 그룹으로 묶어 관리합니다.

피그마 Variable 시스템을 활용한 토큰 구축

• 시스템 분리 원칙: 폰트 스타일(Text Style)은 피그마의 기본 Text Style 시스템을 사용하고, Color, Spacing, Radius 등은 Variable로 구축합니다.

• Color Variable: 역할 기반 토큰(예: color/accent, color/text/primary)을 변수로 생성하여 일관되게 적용합니다.

• Spacing & Radius Variable: 4px/8px 단위의 여백 수치와 컴포넌트 라운드 값을 변수로 관리하여 디자인의 규칙성을 유지합니다.

개발자 전달을 위한 최종 가이드

• 컴포넌트 정리: 반복·재사용되는 UI는 Component로 정리하고, Variant/Properties를 일관되게 구성합니다. 단순히 화면에 보이는 개수만큼 컴포넌트를 만들지 않습니다.

• 자산 정리: 로고·아이콘·이미지 등 개발에 사용되는 자산은 의미 있는 이름과 적절한 형식(SVG, PNG 등)으로 정리하고, 동일 자산을 중복 생성하지 않습니다.

• 레이어 정돈: 의미 없는 Frame 123 대신 Header, Header Content, Header Actions, Footer Navigation과 같이 콘텐츠 역할과 레이아웃 관계가 드러나는 이름으로 정돈합니다.

• Dev Mode 활용: CSS로 구현되는 레이아웃, 크기, 간격, 색상, 타이포그래피 등의 값이 의도대로 전달되는지 최종 검수합니다.
