Figma & Web Design System Reference

화면의 구조를 만들고, 요소 사이의 관계를 잡으며, 반복되는 UI 요소와 스타일을 효율적으로 관리하는 통합 기준서입니다.

01 · DESIGN STYLE & ROLE

역할 명칭(Role Name) 중심의 스타일 등록

화면을 구성할 때 색상값(#111111)이나 크기(48px)를 직접 입력하지 않고, 역할 이름(Role Name)으로 피그마 스타일(Style)에 등록하여 재사용합니다.

❌ 값 직접 지정 (하드코딩)

글자 크기 48px, Bold, 색상 #111111...
새로운 화면을 만들 때마다 치수와 색상값을 다시 기억하고 일일이 지정해야 합니다.

⭕ 역할 이름으로 등록 (스타일 사용)

Hero Title, bg/light, text/main...
역할 이름을 미리 등록해 두면 클릭 한 번으로 통일된 레이아웃 디자인을 빠르게 완성할 수 있습니다.

04 · SPACING GUIDE

스페이싱(Spacing) 적용 기준 및 범위

UI 요소 간의 간격과 여백을 일정한 규칙으로 관리하여 화면의 가독성과 시각적 균형을 높이는 체계입니다.

📌 스페이싱 단위를 유연하게 바라보는 3단계 기준

화면을 구성할 때 아래의 3가지 공간 개념에 대입하여 유연하게 적용합니다."

1. 글자·아이콘 붙이기 (4px ~ 12px)

버튼 안의 아이콘과 글자 사이, 또는 입력창과 라벨처럼 서로 밀접하게 붙어 있어야 하는 아주 작은 요소 간의 간격입니다.

2. 카드·그룹 묶기 (16px ~ 40px)

카드 안쪽 여백이나 카드와 카드 사이, 제목과 본문처럼 하나의 작은 내용 묶음(그룹)을 만들 때 쓰는 간격입니다.

3. 큰 영역 나누기 (48px ~ 128px)

상단 히어로 영역, 서비스 소개, 하단 푸터처럼 완전히 다른 주제의 큰 구역(섹션)과 구역 사이를 큼직하게 띄울 때 씁니다.

05 · ACCESSIBILITY

웹 접근성(Accessibility) 3대 매너

사용자 누구나 편안하게 읽고 정확히 조작할 수 있도록 화면 설계 단계에서 반드시 지켜야 할 기본 규칙입니다.

1. 명도대비 (눈이 편안한 적정 대조)

배경과 글자색의 차이가 적어 너무 연하면 글자를 읽기 힘들고, 반대로 완전한 흑백(#000000 / #FFFFFF)처럼 명도 대비가 극단적이면 눈에 강한 자극과 피로를 줍니다.

선명하면서도 눈이 편안하도록 완전한 검은색 대신 소프트 다크 톤(#111111, #222222)을 활용해 적절한 대비를 형성합니다.

2. 글자 크기 및 다각적 위계 표현

데스크톱 본문은 최소 16px 이상(18px 권장)을 기본으로 설정하며, 뱃지·캡션·주석 등 아무리 작은 부가 요소라도 가독성 및 웹 접근성을 위해 최소 14px 이상을 확보합니다.

또한 정보의 중요도는 단순한 크기뿐만 아니라, 두께(Bold)와 색상의 농도(Color Depth), 주변 여백(Spacing), 레이아웃 구조를 함께 조합하여 더욱 정돈되고 명확한 위계를 만들 수 있습니다.

3. 터치 및 조작 영역 (사용자 조작성 향상)

버튼 및 주요 클릭 요소를 손쉽고 정확하게 조작할 수 있도록 충분한 조작 영역과 여백을 확보합니다.

  • 주요 버튼/아이콘: 타겟 영역을 넉넉하게 확보(권장 44×44px 이상)하여 누르기 쉬운 조작감을 제공합니다.
  • 하단 텍스트 링크 (푸터 등): 최소 18px 글자 크기와 150% 이상(최소 27px 높이)의 행간을 확보하여 자연스러운 터치 영역을 형성합니다.
06 · USEFUL TOOLS

피그마 내장 기능 및 추천 플러그인

작업 속도를 높여주고, 피그마 스타일과 데이터 관리를 손쉽게 돕는 도구입니다.

💡 피그마 내장 기능: Color Contrast (명암비 검수)

별도 플러그인 없이 피그마의 Color Picker 패널 내부에서 텍스트와 배경 간 명암비가 웹 접근성 표준(WCAG AA/AAA)을 충족하는지 실시간으로 바로 확인할 수 있습니다.

Content Reel

더미 데이터(사람 이름, 프로필 사진, 날짜, 주소 등)를 간편하게 채워 넣을 수 있습니다.

Lucide Icons / Feather Icons

웹 표준 개발에서 가장 흔히 쓰이는 깔끔한 벡터 아이콘 라이브러리를 즉시 불러옵니다.

Batch Styler

등록해 둔 수많은 컬러 스타일과 폰트 스타일을 한곳에서 일괄(Batch)로 한 번에 변경할 수 있습니다.

Unsplash

카드나 히어로 영역에 들어갈 고화질 실사 이미지를 클릭 한 번으로 적용합니다.

다음 단계 미리보기 (수행 2차 예정)

이번 1차 프로젝트에서는 기본 스타일(Style) 및 필수 컴포넌트(Component)를 익히고, 다음 2차 프로젝트에서 변수(Variables)와 세트 관리로 확장합니다.

반복 UI의 컴포넌트화와 상태 관리

• 기본 컴포넌트 (❖): 반복해서 사용하는 버튼과 카드를 컴포넌트로 만들어 수정 사항을 한 번에 반영합니다.

• Variants (컴포넌트 세트): Hover, Active, Disabled 등 버튼이나 입력창의 상태별 디자인을 한 그룹으로 묶어 관리합니다.

피그마 Variable 시스템을 활용한 토큰 구축

• Color / Spacing / Radius Variable: 수치화된 간격 값과 Border, Radius 등의 스펙을 변수로 관리하여 다크모드나 테마 변경에 대응합니다.

개발자 전달을 위한 최종 레이어 정돈

• 레이어 이름 지정: 의미 없는 Frame 123 대신 Header, Card List, Footer Navigation처럼 역할이 드러나는 명확한 이름을 작성합니다.

• Dev Mode 활용: CSS로 구현되는 레이아웃, 크기, 간격, 색상, 타이포그래피 값이 정확히 반영되었는지 확인합니다.
